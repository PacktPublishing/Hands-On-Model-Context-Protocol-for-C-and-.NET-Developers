# Chapter 12 — Quiz answers

1. `JobStatusStore` raises the event from the `BackgroundService`'s thread-pool context, outside the Blazor renderer's synchronization context. Calling `StateHasChanged()` there cannot safely schedule a render. The handler must marshal the update onto the component context with `InvokeAsync(StateHasChanged)`. The component should also unsubscribe from `OnStatusChanged` in `Dispose` so the store does not retain and invoke a destroyed component.

2. Caching `book_flight` can return an old confirmation for a later request without sending the new booking to the server. The UI then claims that a booking succeeded even though no new reservation was created; depending on the cache key, it can also expose another request's stale confirmation. The decorator must cache only explicitly allow-listed read tools such as `search_flights` and `get_itinerary`. Write tools such as `book_flight`, `cancel_flight`, and `process_payment` must always bypass both cache reads and writes and call the server.

3. A singleton orchestrator can retain conversation, MCP session, cancellation, or scoped dependency state from one job and expose it to another. Concurrent jobs can also mutate that shared state at the same time, producing mixed responses, protocol-state errors, and cross-user data leakage. Creating an `IServiceScope` for each job resolves a fresh `ReActOrchestrator` and fresh scoped clients, isolates that job's state, and disposes all of its scoped resources when processing completes.

4. The `await foreach` starts from a Blazor event handler and its continuations resume on the component's renderer synchronization context, so `StateHasChanged()` executes on the correct context. A callback raised by a `BackgroundService` runs on a thread-pool thread and has no access to the renderer context. It must use `InvokeAsync(StateHasChanged)` to enqueue the render on the component's dispatcher; otherwise the update may be rejected or never rendered.

5. The booking depends on the earlier search result, so replaying it first can reference an unavailable or unknown flight and fail, or execute against stale state. Replay must use an explicit, stable submission sequence rather than relying on database row order. Store a monotonic sequence value when enqueueing and query with `OrderBy(entry => entry.Sequence)` (or order by full-precision `SubmittedAt` and then by such a sequence as a tie-breaker). This preserves causal ordering even when timestamps collide.

6. Add `aria-live="assertive"` to the element whose content changes when connectivity is lost. The `assertive` value asks assistive technology to announce the urgent offline state immediately rather than waiting for the current speech queue to finish. A non-urgent status could use `polite`, but loss of connectivity affects the user's current operation and warrants `assertive`.
